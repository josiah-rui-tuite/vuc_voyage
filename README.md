# Waypoint（VUC台帳エディタ）

`vuc_ledger.html` ― 単一HTML。仕様は `../daicho/smed_r05.md`（v4.1 / スキーマ `vuc-ledger/4`）。
外部依存なし（CDN・フォント・画像への通信をしない）。UTF-8。約322KB（付録F.2の上限400KBの範囲内）。

## 開き方

- **ダブルクリック**（`file://`）― そのまま動く。保存は「自動保存＝下書き、JSON＝正式」
- **簡易サーバ**（`python -m http.server` など）― `Ctrl+S` で選んだファイルへ上書き保存できる

どちらを選ぶかは決めなくてよい。起動時に能力で判定し、上書きが実際に落ちたらその場でダウンロードへ切り替える。

## 案内（仕様に無い、実装側の追加）

実際に使うと「いま何をしているのか」が見えない、という指摘を受けて足した。**判定には一切関わらない。**

- **航海図の凡例と［詳しく見る］**：帯と丸の色が何を意味するかを凡例で出す（宣言済み＝緑／次に宣言できる段＝青／まだ＝灰。
  色だけで区別させず、帯・丸・言葉の3つで同じことを言う）。［詳しく見る］を ON にすると6区間が縦に伸び、
  **各段に「要る事実」を欄の名前で全部並べる**（済みに ✓、まだに …、まだの欄はその場で押して書ける）。
  止める条件と、止めない注意（warnStop）は見た目を分けてある。**設定は端末に覚える**（`sme.vucledger.v4.voyageDetail`。
  台帳のデータではないので JSON には入れない）。L0〜L5 の見出しだけでは、その段までに何を確かめるのかが分からない、という指摘で足した。
- **航海図**（画面上部・常設）：L0〜L5 を6区間の帯で出す。**帯は「どこまで確かめ終えたと言えるか」で、
  作業の順番ではない。** 各段には「そう宣言できる状態」と「そう言うために要る事実」（付録Dの必須欄から毎回生成）を出す。
  宣言済みの段・次に宣言できる段・そのために**まだ要る事実の件数と名前**を出す（割合や点数は出さない。R3・R7）。
  **「欄を埋めても段は上がらない。宣言するのは人で、場所は画面3の［L◯へ上げる］だけ」を常設で書く**
  （実際に使った著者が「L0で全部入力したのに L0 のまま」で詰まったため）。
  欄が埋まると残りが減り、「直近の前進」に log から2件出る。
  書き込みの節目（VUCメモ／VUC-Lite／判定できるVUC）は「どこまで書いたか」の別のものさしとして並べる

  航海日誌＝記入結果を確認する／設定＝しきい値と保存先／使い方＝はじめての1周。航海図の見出しにも、いま開いている画面がどの区間かを出す

  固定順序（6.8）は**いま何が前進を止めているかの順**であって、上から順にやらなければならない手順ではない
  （とくに順序6「次の段に要る欄」は、同じ段の中では順不同）。順番に縛られると、
  出た1件が今日やれないときに［測る・判定する］へ逃げるしかなく、1件ずつ出す画面の意味が無くなる。
  **飛ばした記録は `S.skipped` に置き、台帳には書かない**（飛ばしたことは事業の事実ではない）。
  だから開き直せば、飛ばした件はまた最上位から出る。全部飛ばすと記録を捨てて先頭へ戻すので、
  連打しても同じ案件の中を回り続け、行き止まりにならない（検査 `Skip-cycle`）

## 直した不具合：書いた値が保存で消えていた

**現行損失に 8,000,000 と入れて［保存］を押しても値が入らず、同じ欄が「今日の一手」に出続ける**、という報告を
実機で再現した。原因は1欄編集面の「この欄の状態」の既定が**「まだ測っていない」**（空のセルの現在値）で、
保存側が `状態 === 値を書く` のときしか値を格納していなかったこと。**入力が黙って捨てられていた**（silent failure）。

直したのは3か所 ―― (1) 空のセルを開いたときの既定を「値を書く」にする、(2) 値を打ったら状態を「値を書く」へ寄せる、
(3) 状態を変えて値を捨てるときは必ず知らせる。加えて保存側にも最後の砦を置いた（**値が書かれていれば、それは値である**。
「該当なし」を明示したときだけ消す）。対象は cell を持つ18欄すべて（単一値11・期待実測7）。
自己テスト `Edit-keep` が見ている。直す前のコードに戻すと落ちることを確認済み。

## 不変条件テスト（付録E）

［設定］の下「不変条件テスト（付録E・11件）を走らせる」。**30件すべて通る**（Chromium 149）。
E1〜E11 に加えて、付録C・D・Fの形（51欄・6段・6しきい値・Core判定8欄）・雛形の過不足（`C-tpl`）・一手の3行に埋め残しが無いこと（`TPL-fill`）・
何も止めていないメモが機械的導出より後ろに出ること（`O9`）・手で `other` にしたメモが同じ欄の一手を落とさないこと（`O9b`）・
昇格を止めている層が一手として名指しされること（`T7c`）も検査する。

`O9` / `O9b` / `TPL-fill` / `T7c` は、欠陥を入れ直して**実際に落ちること**を確かめてある（順序9に雛形2を当てる版で `O9` と `TPL-fill` が落ち、
重複排除を順序で判定する版で `O9b`、トレースを `referenced` で接続扱いにする版で `T7c` が落ちる）。通ることだけを見た検査ではない。

**E1・E3・E10 は、仕様だけを読んだ別人格が書き直した**（付録E：検査の主体を作った本人にしない）。
実装のコードを見る前に仕様から設計し、そのうえで既存の3件と差し替えてある。
残る検査は実装者が書いたものなので、**これだけで出荷判断はしない**。実機と被験者の側はまだ開いている（下記）。

## 6.4.5 の実機検証：済んだもの（Chromium 149・Windows）

`file://` は自動化ツールが開けないため、Chromium 本体を CDP で直接叩いて確かめた。**Chromium 1つだけの結果である。**

| # | 項目 | 実測 |
|---|---|---|
| 1 | `file://` の localStorage が永続するか | **永続する**。ブラウザを閉じて開き直しても、プロジェクト名・VUC・空欄3区分がそのまま戻る |
| 2 | 別ディレクトリの別HTMLと格納域が混ざらないか | **混ざる**。同じツールを別フォルダに置くと、下書きと最近のプロジェクト一覧を共有する。JSONは別なので正本は分かれる。画面の説明に1行足した |
| 3 | JSONの往復で日本語が壊れないか | **壊れない**。全角空白・記号・約物を含めて一致。BOMなし。ツールに読み戻して往復一致 |
| 5 | 能力判定がモードを分けるか | `file://` でも `showSaveFilePicker` は**存在する**ので、起動時の暫定判定は上書きモードを選ぶ。`http://localhost` とは**格納域が分かれる**（同じファイルでも開き方を変えるとデータは見えない） |
| 6 | 関数があるのに保存が失敗する環境が実在するか | headless では `AbortError` で落ちた（ダイアログを出せないため）。取り消しと区別できないので、文面を「どちらでも次にやることが分かる」形に直した |
